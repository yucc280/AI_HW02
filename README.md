# 实验二：搜索算法

## 1. 项目简介

本项目实现了当代人工智能实验二的四道搜索算法题目，包括 A* 寻路、加权地形搜索、Minimax 与 Alpha-Beta 剪枝，以及结合 A* 和博弈搜索的宝藏分配问题。

在基础任务之上，针对问题四进一步设计了**基于即时收益的动态节点排序策略**，通过改变 Alpha-Beta 的子节点访问顺序提高剪枝效率，并在**不同搜索规模、深度及宝藏价值分布**下进行对照实验。

## 2. 项目结构

```text
./
├── q1.py                 # 题目一：A* 迷宫寻路
├── q2.py                 # 题目二：加权地形 A*
├── q3.py                 # 题目三：Minimax 与 Alpha-Beta
├── q4_treasure.py        # 题目四：宝藏分配基础实现
├── q4_extension.py       # 题目四：动态排序策略
├── q4_experiment.py      # 题目四：扩展对照实验
├── plot_results.py       # 实验结果可视化

```


## 4. 运行方法

所有测试样例已写好内置在程序中，直接在项目根目录执行以下命令即可：

### 4.1 基础实验

```bash
python q1.py
python q2.py
python q3.py
python q4_treasure.py
```

分别运行四道基础题，输出最优路径或代价、博弈最优得分，以及相关搜索统计。

### 4.2 创新实验

```bash
python q4_extension.py
python q4_experiment.py
```

其中：

- `q4_extension.py`：验证即时收益动态排序策略。
- `q4_experiment.py`：比较 Minimax、固定左右顺序 Alpha-Beta 和动态排序 Alpha-Beta，在不同宝藏数量、搜索深度及价值分布下的表现。

### 4.3 结果可视化（可选，与实验无关，仅有绘图作用）

```bash
python plot_results.py
```

运行后在 `figures/` 目录下生成两张图：

- `fig1_search_efficiency.png`：不同搜索规模与深度下的叶子访问数对照
- `fig2_value_distribution.png`：不同价值分布下的搜索效率对照

绘图脚本会使用此前运行程序已记录的实验结果，不重新执行搜索算法。

## 5. 实验结果与验证

除`plot_results.py`外，运行相应程序后的结果均在终端输出。

基础实验结果：

| 题目 | 结果 |
|---|---|
| 题目一 | 最短路径长度为 7，曼哈顿启发函数减少搜索节点 |
| 题目二 | 最小移动代价为 7，修正曼哈顿启发函数减少搜索节点 |
| 题目三 | 测试树最优得分为 5，Alpha-Beta 保持结果正确并减少叶节点访问 |
| 题目四 | H=2：T2，收益差 -1；H=4：T3，收益差 3 |

创新实验采用即时收益：

\[
Gain(p,T_i)=V_i-d(p,T_i)
\]

对候选宝藏进行动态排序，在不改变 Minimax 最优收益差的前提下，研究不同访问顺序对 Alpha-Beta 剪枝效率的影响。这里分别在**不同搜索规模、深度及宝藏价值分布**下进行对照实验。

关于**搜索规模**，这里在原始的四个宝藏地图基础上，新构建了如下有六个宝藏的地图（把两个原来代价为 1 的位置改成了 T5 和 T6）：
```text
      0   1   2   3   4   5   6
 0    A   1   T5  X   2   1   T1
 1    1   X   6   X   1   X   1
 2    1   1   T2  1   1   T6  1
 3    X   1   X   8   X   1   X
 4    1   1   1   1   T3  1   1
 5    1   X   9   X   1   X   1
 6    T4  1   1   X   1   1   B
```
其中 T5 价值为5，T6 价值为 8.

关于**宝藏价值分布**，是针对六个宝藏的地图，仅修改 T1~T6 的宝藏价值，保留各点的位置不变，具体设置如下：
| 场景    | T1 | T2 | T3 | T4 | T5 | T6 |
| ----- | -- | -- | -- | -- | -- | -- |
| 原始配置  | 9  | 6  | 7  | 7  | 5  | 8  |
| 价值差异大 | 15 | 3  | 12 | 4  | 2  | 14 |
| 价值相近  | 7  | 7  | 8  | 7  | 8  | 7  |

实验主要统计：

- `leaves`：访问的叶子节点数。
- `nodes`：访问的总节点数，包括内部节点与叶子节点。
- `sort_calls`：动态排序调用次数。
- `sort_items`：动态排序累计处理的候选元素数。
- `time_ms`：单次搜索执行时间。


这部分具体的算法设计、对照分析及实验结论见实验报告。

## 6. 复现说明与局限性

1. 基础测试部分采用实验要求中提供的地图和博弈树；扩展场景使用了新增配置，具体配置内容见上，在第 5 点内提到，代码按照上述内容定义了固定配置。本次实验只讨论上述提到的几个情况，如需进一步测试其他配置需修改代码逻辑。
2. 动态排序不保证在所有情况下访问最少的节点，其效果依赖于搜索深度、状态与候选访问顺序。
3. `time_ms` 为单次执行时间，会受到运行环境影响，每次运行结果具有不稳定性，不能保证复现时该项结果一致；实验主要通过节点访问数量分析搜索效率。
4. 绘图数据由已完成的实验结果整理而来，暂时只设置为固定逻辑。
